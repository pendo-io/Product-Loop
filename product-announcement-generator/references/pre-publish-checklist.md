# Pre-publish checklist

Work through this list before handing over (or saving) the draft. The goal is an internal announcement any reader can scan in under 10 seconds and act on immediately.

## Required information

- [ ] **Product area**
- [ ] **Feature name**: clear and concise
- [ ] **Status**: one of your saved status values, or the default GA, Open Beta, Closed Beta, EA, or Coming Soon (use Coming Soon for an announcement written before launch; switch it before posting)
- [ ] **Value hook**: one line, concrete, reader-facing
- [ ] **Who cares most**: one or more roles at a company that care most about the change (for example PM, CPO, CTO, sales rep, support lead), not an internal team
- [ ] **First external resource**: help article, blog post, marketing page, or in-app path
- [ ] **Questions channel**
- [ ] **Regional availability**: confirmed (global, or specific regions called out in the body)
- [ ] **Visual**: a screenshot or GIF sourced: checked the feature record for an image; if none, offered to capture it with a browser tool (if available), and asked the user for the environment URL or the image if the environment is unknown. A visual is expected, not optional.

## Quality checks

- [ ] Header line fits on one line
- [ ] Same emoji bookends both ends of the header
- [ ] **Header is bold**, value hook included, and Status is filled in (no `[Status]` or `[Date]` placeholders)
- [ ] Value hook is concrete (no "improved experience" / "enhanced workflow" filler)
- [ ] Body is 2 to 3 sentences, not 4+
- [ ] "Who cares most" names roles, not an internal team, and isn't a long list
- [ ] "From here" is 3 lines (4 only if action genuinely splits across audiences)
- [ ] Questions channel is the last line of "From here"
- [ ] If feature isn't available in all regions, regional line is in the body
- [ ] If attachments exist, the `_Attached: …_` italic line is at the bottom
- [ ] Only the template's parts appear: header, 2 to 3 sentence body, any availability line, "Who cares most", "From here", and the optional attachments line
- [ ] **No dashes**: no em dash or en dash anywhere, header or body
- [ ] **No internal shorthand**: no acronyms or jargon internal readers outside the product team won't know (for example, a project codename or team acronym); product names and terms match the user's glossary if there is one
- [ ] **No ticket ids**: no ticket ids, keys, or flag names in the header, body, or link text (a ticket reference only inside a URL)
- [ ] **No dates**: no launch date, "as of", "today", "now available", or "now live" in the header or body (state the capability, not the timing; "now" plus a capability verb, such as "You can now…", is fine)
- [ ] **Mechanical check** (SKILL.md Step 2) passed: no dashes, dates, bare ticket keys, "now available", or "now live" in the visible text (or, after two fix passes, remaining hits named at hand-back)
- [ ] **Brand voice** (if one was confirmed): applied to tone and word choice only; any voice rule that conflicts with the format, dash, date, or ticket-id rules was set aside and named to the user

## Formatting

- [ ] Bold uses `**text**` (double asterisks)
- [ ] Bullets use `* ` (asterisk + space)
- [ ] Links use `[text](url)`
- [ ] Channels appear as plain text, such as `#channel-name`, with no Slack `![](#id)` or `<@U…>` codes
- [ ] No placeholder text remaining (unless intentional `[TBD]`)

## The 10-second test

Read the draft start to finish. If it takes longer than 10 seconds, cut something or move it to the thread. The most common culprits:

1. A fourth body sentence that should be cut or moved to a thread reply
2. A long list of roles instead of the ones who care most
3. Three+ resource links when one would do
